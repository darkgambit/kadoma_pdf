# Requested features vs. delivered offline version

**Legend:** Working = implemented local operation. Optional = requires an external
local engine. Partial = useful implementation with important limitations.
Not included = no fake/placeholder implementation.

| Original category | Status | Delivered |
|---|---|---|
| 1. PDF creation | Working + optional | Blank PDF, images, local HTML/text, and a full **combine** window. Word/Excel/PowerPoint import via locally installed LibreOffice. No live webpage capture. |
| 2. PDF editing | Working / partial | **Direct on-page text editing:** click a line and type over it in place, with a matched size/colour/font/rotation box, Enter to apply, Esc to cancel, click-away to apply, and an empty box to delete the line. Double-click starts an edit under any tool. Longer replacements grow into free space to the right and keep their font size; they shrink only when they meet other text or the margin. **Arabic, Hebrew, Persian and Urdu** are shaped, joined and laid out right-to-left, read back as the letters typed, and searchable; the in-place editor switches direction for them and RTL replacements grow leftwards. Plus text/image insertion, embedded-image replacement/deletion, page insert/delete/reorder/rotate/duplicate. No original source required. Editing is one visual line at a time; no arbitrary vector editing or font-perfect paragraph reflow. |
| 3. Convert PDFs | Working / partial | Editable `.docx` text/tables/images, detected-table `.xlsx`, `.pptx` page-image slides, PNG/JPG ZIPs, plain text. Original formatting is not guaranteed. |
| 4. E-signatures | Partial | Typed/drawn visual signature images. No certificate signing, identity verification, remote requests, tracking, or agreement service. |
| 5. Form creation/filling | Working | PDF text fields, **date fields with a calendar picker**, checkboxes, dropdowns; supported existing fields filled in PDF. Sign visually. |
| 6. Security/protection | Working, not audited | AES-256 encryption, opening/owner passwords, advisory permissions. Actual redaction of selected content with history clearing and metadata/attachment stripping. Verify output before sharing. |
| 7. Comments/collaboration | Partial | Local comments/highlights and annotation deletion, saved in PDF. Share exported files manually. No synchronized multi-reviewer service. |
| 8. OCR | Optional / partial | Local Tesseract produces saved searchable 200-DPI raster pages; selected page forms/annotations are flattened. Export recognized text to Word. Scan-text replacement is localized with white pixel erasure; recognition/layout must be checked. |
| 9. Cloud integration | Not included | No account or network sync. This matches the selected offline-first scope. |
| 10. AI features | Working offline, optional model | An **AI reading** view with two tools. **Summarise**: an offline extractive summary — the sentences that best represent the document, ranked by the frequency of the words they contain and quoted exactly as they stand — plus the document's key terms. **Build a form from a prompt**: ordinary words ("full name, email, date signed, and a checkbox to agree") become **real PDF form fields**, typed and laid out on a new page in one undoable step. Both run entirely on this computer and need no network, and **neither is a language model**: they do not paraphrase, do not invent, and cannot answer questions. **A model is optional and off by default.** Somebody may connect their own OpenAI-compatible endpoint, model name and key, after which summaries are written by that model and forms designed by it; the document's extracted text is sent to the endpoint they configured, only after they agree to it, and the key is held in memory for the session and never written to disk. There is no account, no bundled key and no AI vendor relationship. |
| 11. Send / share a PDF | Working (desktop) | Share writes an export to a stable temporary share folder, then offers: an email **with the file attached** (a real `.eml` handed to your mail program), a plain **`mailto` draft** with the file on the clipboard, **copy the file** itself for pasting into any app, and **show it in its folder**. KADOMA never sends anything and stores no mail credentials. `mailto` cannot carry an attachment, so that route is labelled honestly rather than faked. Unavailable in the hosted browser preview, where the endpoints refuse the request. |
| 12. Be the default PDF app | Working (Windows desktop) | Registers KADOMA as a PDF handler for the current user only — no administrator rights — then opens the Windows Settings page for confirmation. Windows blocks any silent claim of a file type, so that last step is the user's. Double-clicking a PDF opens it in the already-running window instead of starting a second copy. On macOS the PDF type is declared in the bundle and the app appears under "Open With". |

Bound to Ctrl/⌘ S and Ctrl/⌘ Shift S, and to two buttons beside Export. The header says **Saved** or **Unsaved changes** for the document on screen, and the engine decides that from the revision it last wrote, not from what the interface remembers. An overwrite is **refused, with a reason, when the file changed on disk since it was opened** — a sync client or another editor is never silently replaced; Save as is still offered. The bytes go to a temporary file beside the destination and are then moved into place in one step, so a failed write cannot leave a half-written PDF where a good one was. A password-protected file **keeps its encryption, both passwords and its permissions** when it is saved over (measured, not assumed). A document that came from the browser picker, from a blank page, or from a converted `.docx` has no file to write over, so its first Save asks where to put the copy rather than overwriting the source format. In the browser preview, which has nowhere to write, both buttons explain that and offer the export instead. |

## AI reading: what is not included

- **The offline reading is not a language model.** It selects sentences that are
  already in the document and quotes them; it does not paraphrase, summarise in
  its own words, translate, or answer a question about the content. The interface
  says which of the two readings produced every result, because presenting an
  extraction as though a model wrote it would misrepresent what the reader is
  looking at.
- **No question answering, chat, translation, rewriting or document generation.**
  There is no conversational interface and no free-text output beyond a summary.
- **The offline summary is language-neutral in method, not in tuning.** Ranking is
  by how often a word recurs within the document, which works in any script, but
  the stop-word list that sharpens it is English. Sentence splitting recognises
  Latin, Arabic and CJK terminators.
- **The prompt-to-form parser recognises field names, not intentions.** It knows
  the words people usually write — name, email, date signed, address, checkbox,
  dropdown with choices — and takes anything in quotes verbatim. A request it does
  not recognise is refused with an example rather than guessed at.
- **A connected model is not verified.** Whatever the endpoint returns is
  validated for shape (a field type this application can build, a label it can
  use) but not for truth. Nothing checks that a model's summary is accurate.
- **Only the extracted text is sent, never the file** — and never the document's
  images, annotations or form values. A scanned document with no OCR has no text
  to send.
- **No key is stored.** Closing the application forgets the connection, and the
  key is never written to disk, logged, or returned by any endpoint.

## The workspace: what is not included

- **No tabs, no split view, no side-by-side comparison.** One document is on
  screen at a time; the others are held open and reachable from the switcher.
- **Documents are edited in memory and written only on request.** Nothing is
  written to disk on open, on edit or on close — only Save, Save as or an export
  writes anything. Closing a document or quitting therefore loses whatever has
  not been saved or exported, and the document on screen warns before it is
  closed with unsaved changes. The others do not, because they are still listed
  and still open.
- **No session restore.** A restart begins with the sample document; the open
  documents from the previous run are not recovered.
- **The cap is six.** Opening more closes the oldest without asking, which the
  switcher menu states.
- **The page thumbnails are not on screen by default.** The Pages view shows every page as a grid, which is where pages are reordered and selected; the side column is a convenience you switch on.
- **The menu bar, the panels and the zoom are per session.** Nothing is remembered between runs, because this application writes no preferences to disk.

## Splitting files: what is not included

- **A protected PDF cannot be split.** Every part would need re-encrypting with
  both passwords again, and handing back an unprotected copy would be worse than
  saying no, so the window refuses with a message pointing at the way that works:
  unlock an authorized copy first, then split that.
- **No page-level de-duplication.** A range typed twice produces that page in two
  parts, which is sometimes the point.
- **No automatic outline, bookmark or page-label rewriting.** Pages travel with
  their annotations and form fields; a new table of contents for the parts is not
  built.
- **No fixed file size target.** Cuts are decided by page count, not by bytes, so
  a document of mixed page sizes will produce parts of uneven size.
- Splitting is local, so it also works in the hosted browser preview — where the
  document is processed in that workspace, as the preview states.

## Right-to-left text: measured limits

- Shaping, joining, right-to-left order and read-back of the typed letters are
  correct; Arabic is also searchable.
- **Arabic-Indic digits may return in an equivalent variant.** A font may map the
  digit glyphs to the Extended/Persian block, so `٩٩٩٩` can be stored as `۹۹۹۹`.
  They render identically and search folds the variants, but extracted text is
  not byte-identical to the input.
- **Font round-trip quality is measured, not assumed.** MuPDF derives its reverse
  text mapping from the font, and some fonts map ligature glyphs back to the
  wrong characters — correct on the page, corrupted when the line is edited
  again. Measured on Windows: Arial and Tahoma round-trip exactly; Segoe UI,
  Dubai, Microsoft Sans Serif and Calibri lose the lam-alef ligature. The app
  measures the fonts present and reports `exact` or `approximate`.
- The bundled Noto Sans Arabic fallback is **approximate** (renders correctly,
  does not round-trip lam-alef exactly). It exists so Arabic still works where no
  Arabic system font is installed.
- Bidirectional mixed Arabic/Latin lines rely on MuPDF's bidi implementation and
  have not been separately verified.

## Combining files: what is not included

- **No page de-duplication or comparison.** If the same page is in two files you
  combine, it appears twice. Nothing scans the sources for repeats.
- **No outline is rebuilt across the join.** Bookmarks and named destinations
  that came from a source travel with the copied page, but the combined document
  gets no new merged table of contents, and duplicate destination names are not
  renamed.
- **No per-file rotation, scaling or cropping** while combining. Those are page
  operations, applied afterwards in Organize.
- **A page selection is a selection, not a filter.** `2-3, 7` takes exactly those
  pages in that order; it cannot exclude pages, and it is not remembered between
  files.
- Combining is local, so it also works in the hosted browser preview — where the
  files are processed in that workspace, as the preview states.
